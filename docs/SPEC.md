## 1. Обзор и цели MVP

MVP — десктопная игра для Windows (Steam), в которой 2–12 незнакомцев проходят короткий 2D-уровень вместе, общаются голосом по кнопке и вынуждены помогать друг другу. Цель MVP — не релиз, а проверка одной гипотезы на закрытых плейтестах.

**Главная гипотеза:** случайные люди, поставленные в ситуацию, где без кооперации не пройти, начинают разговаривать и хотят сыграть ещё раз той же компанией.

**Метрики плейтеста** (собираются локальным логом и опросом):

- доля игроков, хотя бы раз нажавших push-to-talk за забег;
- среднее число заявок в друзья на игрока после забега;
- доля игроков, нажавших «Ещё раз с этой компанией»;
- доля игроков, начавших второй забег в той же сессии.

**Жанр и вид:** кооперативный социальный 2D-платформер, вид сбоку, блочная графика.

**Платформа:** только Windows x64 через Steam. Linux и macOS — по возможности, не блокируют MVP.

**Ключевые отличия от исходного ТЗ:**

- размер забега 2–12 игроков (константа, расширяемая до 16), а не 50;
- длительность забега 5–8 минут, а не 10–15;
- нет наград за скорость и нет лидербордов: награждается помощь и совместные действия;
- часть препятствий проходится только вместе (кооп-ворота с запасным таймером на случай малого онлайна);
- мобы и монеты общие для всех, а не локальные у каждого;
- экран результатов показывает сначала тех, с кем было реальное взаимодействие;
- друзья, лобби, инвайты, голос и сетевой relay берутся из Steam, собственного бэкенда нет.

**Аудитория и возраст:** вопрос возрастных ограничений отложен до публичного запуска. Закрытые плейтесты MVP проводятся только со взрослыми участниками по приглашению.

## 2. Технологический стек

Игра пишется на Godot 4 (GDScript со статической типизацией), вся сетевая и социальная инфраструктура берётся из Steam через GodotSteam. Собственного сервера в MVP нет.

| Компонент | Решение | Лицензия | Назначение |
| --- | --- | --- | --- |
| Движок | Godot 4.x, последняя стабильная версия, для которой есть сборка GodotSteam | MIT | Игра, рендер, физика, UI |
| Язык | GDScript, строгая статическая типизация | — | Весь код игры |
| Steam API | GodotSteam (GDExtension или готовая сборка редактора) | MIT | Лобби, друзья, оверлей, голос, Rich Presence |
| Сетевой транспорт (прод) | SteamMultiplayerPeer из экосистемы GodotSteam поверх Steam Networking Sockets | MIT | P2P через Steam Datagram Relay, IP скрыты |
| Сетевой транспорт (разработка) | ENetMultiplayerPeer (встроен в Godot) | MIT | Запуск нескольких копий игры на одном ПК без Steam |
| Высокоуровневая сеть | SceneMultiplayer, RPC Godot | MIT | Синхронизация и события |
| Голос | Steam Voice (запись и сжатие), воспроизведение через AudioStreamGenerator | — | Push-to-talk и proximity |
| Юнит-тесты | GUT (Godot Unit Test) | MIT | Тесты генератора, логики очков взаимодействия |
| Графика и звук (временные) | Ассеты Kenney | CC0 | Плейсхолдеры |
| Репорты | HTTP POST на webhook (URL в конфиге вне репозитория) | — | Приём жалоб без своего бэкенда |
| Контроль версий | Git + Git LFS для бинарных ассетов | — | — |

**Правила по зависимостям:**

- версия Godot и версия GodotSteam фиксируются в README и в `project.godot` в первый день и не меняются без явного решения;
- точные имена функций и сигналов GodotSteam сверяются с официальной документацией godotsteam.com для выбранной версии, а не по памяти;
- новые плагины и библиотеки добавляются только после согласования;
- все обращения к Steam идут через один автолоад-сервис, чтобы игра запускалась и без Steam (режим разработки).

**Steam App ID:** на этапе разработки используется тестовый App ID 480 (Spacewar) с обязательным фильтром лобби по собственному тегу игры, потому что этот ID общий для всех разработчиков. Для плейтестов регистрируется собственный App ID через Steam Direct.

## 3. Структура проекта и соглашения

Проект — один Godot-проект в корне репозитория; логика разделена на автолоады-сервисы, игровые сцены и сетевой слой с подменяемым транспортом.

**Соглашения по коду:**

- GDScript со статическими типами везде, включая `Array[Type]` и возвращаемые значения;
- имена файлов и переменных в snake_case, классы через `class_name` в PascalCase;
- никаких «магических чисел» в коде геймплея: всё в `balance.tres` или `protocol.gd`;
- сцены не обращаются друг к другу напрямую, связь через сигналы и `EventBus`;
- весь текст интерфейса через ключи перевода (`tr("MENU_QUICK_PLAY")`), языки ru и en с первого дня;
- каждый автолоад имеет короткий комментарий в начале файла: что он делает и чего не делает.

**Аргументы командной строки** (для локальных тестов, передаются после `--` в Godot):

- `--dev-host` — запустить как хост через ENet на порту 7777;
- `--dev-join=127.0.0.1` — подключиться как клиент;
- `--dev-name=Bot3` — имя игрока без Steam;
- `--dev-seed=12345` — фиксированный seed уровня;
- `--bot` — простой бот: бежит вправо и прыгает перед препятствиями (для нагрузочных тестов);
- `--net-lag=150 --net-loss=5` — эмуляция плохой сети в ENet-транспорте;
- `--log-net` — подробный лог сетевых RPC.

## 4. Персонаж: управление, физика, действия

Персонаж — `CharacterBody2D` с отзывчивым платформерным управлением; игроки не могут навредить друг другу, но могут стоять друг у друга на голове. Все числа ниже — стартовые значения в `balance.tres`, их подбирают на плейтестах.

**Управление (клавиатура, все бинды переназначаемые):**

| Действие | Клавиша | Геймпад (желательно) |
| --- | --- | --- |
| Влево / вправо | A / D, стрелки | Левый стик |
| Прыжок | Пробел | A |
| Атака | J или ЛКМ | X |
| Взаимодействие (вытянуть игрока) | E (удерживать) | B (удерживать) |
| Push-to-talk | V (удерживать) | LB |
| Колесо эмоций | Q (удерживать) | RB |
| Быстрые эмоции 1–6 | 1–6 | — |
| Список игроков / меню | Tab / Esc | Select / Start |

**Физика движения (стартовые значения, единицы — пиксели мира):**

| Параметр | Значение |
| --- | --- |
| Макс. скорость бега | 260 px/с |
| Ускорение / торможение на земле | 1800 / 2200 px/с² |
| Управляемость в воздухе | 70% от наземного ускорения |
| Скорость прыжка | 520 px/с |
| Гравитация | 1400 px/с², при падении ×1.4 |
| Макс. скорость падения | 900 px/с |
| Coyote time | 0.10 с |
| Буфер прыжка | 0.10 с |
| Переменная высота прыжка | отпускание кнопки режет вертикальную скорость до 45% |
| Хитбокс персонажа | 28 × 44 px |
| Усиление прыжка с головы другого игрока | скорость прыжка ×1.25 |

Высота обычного прыжка при этих значениях — около 96 px (520² / (2 × 1400)).

**Атака:**

- удар оружием ближнего боя перед персонажем, хитбокс 40 × 32 px, активен 0.12 с, перезарядка 0.35 с;
- работает на земле и в воздухе (бить птиц в прыжке);
- по игрокам урона нет, только визуальный «тычок» и звук, без отбрасывания;
- попадание по мобу определяется локально, затем подтверждается хостом (раздел 6 и 8).

**Столкновения игроков между собой:**

- по горизонтали игроки проходят друг сквозь друга (толкотня в толпе недопустима);
- сверху голова игрока — односторонняя платформа: на неё можно встать и подпрыгнуть выше (кооп-механика «ступенька»);
- удалённые игроки для этого имеют отдельный кинематический коллайдер головы, который следует за интерполированной позицией.

**Урон и падения:**

- здоровья нет; шипы и кактусы дают отбрасывание, мигание 1 с и неуязвимость 1 с;
- падение в пропасть переводит игрока в состояние «Висит» у края (раздел 7) вместо мгновенной смерти;
- из «Висит» игрок возвращается либо помощью другого игрока, либо сам через 8 с (перенос на последний чекпоинт), либо кнопкой «Сдаться» сразу.

**Эмоции:** 6 эмоций-фраз с пузырём над головой на 2.5 с и короткой анимацией: «Привет!», «Спасибо!», «Сюда!», «Подожди!», «Ха-ха», «Помогите!». Перезарядка между эмоциями 1 с.

**Анимации (состояния аниматора):** idle, run, jump, fall, land, attack, hit, hang, pulled_up, help_pull, emote, celebrate. На этапе MVP допустимы простые твины масштаба и поворота блочного спрайта вместо покадровой анимации.

**Камера:** `Camera2D` следует за своим игроком с небольшим опережением по направлению бега, плавное сглаживание, ограничение по границам уровня. Видимая область мира — 1280 × 720 px при любом разрешении окна (stretch mode `canvas_items`, aspect `keep_height`).

## 5. Уровни: структура и генерация по seed

Уровень собирается из готовых вручную секций (chunks) в порядке, который задаёт seed хоста; у всех игроков получается идентичный уровень без передачи геометрии по сети.

**Состав забега:**

1. Стартовая площадка (фиксированная секция): все игроки появляются здесь, 5 с отсчёта.
2. 8 секций из пула, выбранных по seed, с правилом: каждая 3-я секция (3-я и 6-я) — кооперативная (кооп-ворота).
3. Чекпоинт в начале каждой секции.
4. Финишная площадка (фиксированная секция): социальная зона без препятствий, где финишировавшие ждут остальных.

Итого 10 секций. Целевая длительность прохождения — 5–8 минут. Жёсткий лимит забега — 10 минут, после него забег завершается для всех.

**Пул секций для MVP:** не менее 14 секций.

| Тип | Кол-во | Содержание |
| --- | --- | --- |
| Обычная лёгкая | 4 | Пропасти, кактусы, птицы |
| Обычная средняя | 4 | Шипы, движущиеся и падающие платформы, наземные зверьки |
| Кооперативная | 4 | Нажимные плиты, высокий уступ «ступенькой», ворота на N игроков |
| Бонусная | 2 | Золотая цель, много монет, без опасностей |

**Контракт секции (`chunk.gd`):**

- ширина кратна 64 px, от 1920 до 3840 px; высота игровой зоны — 720 px;
- вход и выход на одной высоте пола (y = 576) шириной не меньше 192 px, чтобы секции стыковались;
- секция содержит маркеры: `CheckpointMarker`, `MobSpawn` (с типом и параметрами), `CoinSpawn`, `CoopGate` (если есть), `HangPoint` (у каждой пропасти);
- в `chunk.gd` экспортируются метаданные: `difficulty`, `type`, `min_players_for_coop`;
- визуал из `TileMapLayer` с тайлом 64 × 64 px.

**Генерация по seed:**

- seed — 32-битное целое, генерирует хост при старте забега и записывает в данные лобби и в RPC старта;
- используется только `RandomNumberGenerator` с этим seed, никаких вызовов глобального `randi()` / `randf()` в генерации;
- генератор выдаёт список секций, их смещения по X и полный список спавнов мобов и монет с уникальными `spawn_id`;
- при одинаковом seed результат побитово одинаков на любой машине (обязательный юнит-тест: 1000 seed, сравнение хешей);
- соседние секции не повторяются, одна секция не встречается в забеге больше одного раза.

**Пропасть:** зона `PitArea` под уровнем пола; при входе игрок переходит в состояние «Висит» и визуально зацепляется за ближайший левый край пропасти (точка `HangPoint` на краю, её указывает секция).

## 6. Мобы, монеты и препятствия

Мобы и монеты общие для всех игроков: их движение детерминировано от seed и серверного времени, а решения «убит» и «подобран» принимает только хост. Так все видят одно и то же, а трафик минимален.

**Мобы:**

| Моб | Поведение | Удары до смерти | Награда |
| --- | --- | --- | --- |
| Птица | Летит по синусоиде вдоль участка 400–800 px, высота 96–220 px над полом | 1 | 1 монета ударившему |
| Зверёк | Бегает по земле туда-обратно в пределах платформы, разворачивается у края | 1 | 1 монета ударившему |
| Золотая цель | Быстро летает по сложной траектории на бонусной секции; уязвима, только если её ударили 2 разных игрока в пределах 3 с | 2 (от разных игроков) | 10 монет каждому участнику |

- мобы не наносят урон, только отталкивают при касании (без мигания);
- траектория моба — чистая функция `f(spawn_params, run_time)`, поэтому клиенты рисуют её сами без синхронизации позиций;
- `run_time` — время от старта забега по часам хоста (синхронизация часов в разделе 8);
- убитый моб не возрождается в этом забеге.

**Попадание по мобу (поток):**

1. Клиент локально видит пересечение хитбокса атаки и моба и сразу играет эффект удара.
2. Клиент отправляет хосту `rpc_hit_mob(spawn_id, client_run_time)`.
3. Хост проверяет: моб жив, атакующий в пределах 96 px от расчётной позиции моба на это время (с допуском на пинг), перезарядка атаки соблюдена.
4. Хост рассылает всем `rpc_mob_killed(spawn_id, killer_peer_ids, coins)`; клиенты удаляют моба и начисляют монеты.
5. Если хост отклонил попадание, клиент ничего не делает (эффект удара уже сыгран, это допустимо).

**Монеты на уровне:**

- статичные монеты из `CoinSpawn` видны всем и подбираются по принципу «первый коснувшийся»: клиент шлёт `rpc_pickup_coin(spawn_id)`, хост подтверждает первому и рассылает исчезновение;
- дополнительно за каждую помощь (вытянул игрока из пропасти) — 3 монеты, за прохождение кооп-ворот — 2 монеты каждому участнику, за финиш — 5 монет;
- наград за место на финише и за скорость нет.

**Препятствия:**

| Препятствие | Поведение |
| --- | --- |
| Кактус, шипы | Статичные, отбрасывание |
| Пропасть | Переводит в состояние «Висит» |
| Движущаяся платформа | Движение по пути, детерминировано от `run_time`, без сетевой синхронизации |
| Падающая платформа | Падает через 0.6 с после того, как на неё встал игрок; событие шлёт хост, чтобы у всех упала одновременно; восстанавливается через 5 с |

**Экономика MVP:** монеты хранятся локально в `user://save.json` (поле `coins_total`). Античит в MVP не нужен: монеты тратятся только на косметику в гардеробе (раздел 13). Перенос в Steam Inventory или свой бэкенд — после MVP.

## 7. Кооперативные механики (ледоколы)

Кооперация — ядро MVP: механики ниже создают повод заговорить, а у каждой есть запасной путь, чтобы игрок не застрял при малом числе людей в забеге. Все исходы механик подтверждает хост и отправляет событие в `Interactions` для экрана результатов.

**7.1. Вытянуть из пропасти**

- упавший игрок висит у края в состоянии «Висит», над ним иконка руки и таймер 8 с;
- другой игрок в радиусе 64 px от `HangPoint` удерживает E 0.5 с (полоса прогресса над головой);
- клиент помощника шлёт `rpc_request_pull(target_peer_id)`, хост проверяет дистанцию и состояние и рассылает `rpc_pulled(helper, target)`;
- обе анимации: помощник тянет руку, упавший выпрыгивает на край; помощнику +3 монеты;
- если за 8 с никто не помог — перенос на последний чекпоинт без штрафа;
- упавший может нажать «Помогите!» (эмоция 6), у всех игроков в радиусе 1280 px появляется стрелка-указатель на него.

**7.2. Нажимные плиты и кооп-ворота**

- в кооперативной секции ворота открываются, когда на N плитах одновременно стоят N разных игроков, где N = `min(min_players_for_coop, игроков_в_забеге)` и не больше 3;
- состояние плит считает хост по позициям игроков (плита — зона, хост проверяет снапшоты), ворота открываются событием `rpc_gate_open(gate_id)`;
- после открытия ворота остаются открытыми навсегда;
- **запасной таймер:** если хотя бы один игрок стоит у закрытых ворот 45 с, ворота открываются сами. Так забег не ломается при 2–3 игроках.

**7.3. Ступенька**

- в кооперативных секциях есть уступы высотой 160–176 px, недостижимые обычным прыжком (его высота около 96 px); прыжок с головы другого игрока получает усиление скорости ×1.25, что даёт около 150 px плюс 44 px роста помощника;
- решение: встать на голову другому игроку и прыгнуть с неё (раздел 4, коллизия сверху);
- рядом с уступом — верёвочная лестница, которая опускается, когда хотя бы один игрок оказался наверху (событие от хоста). Так поднимаются остальные, и «ступенька» не стоит внизу вечно;
- запасной путь для одиночки: через 45 с у уступа появляется дополнительная платформа.

**7.4. Золотая цель** — см. раздел 6: убивается только ударами двух разных игроков в пределах 3 с, награда каждому участнику.

**7.5. Колесо эмоций и указатели**

- удержание Q открывает радиальное меню из 6 эмоций, выбор мышью или стиком, отпускание Q подтверждает;
- эмоция отправляется `rpc_emote(emote_id)` через хоста всем, кто в радиусе 1920 px;
- «Сюда!» ставит на 3 с маркер-стрелку в точке, куда смотрит персонаж, виден всем в радиусе.

**7.6. Финишная площадка**

- финишировавшие попадают в безопасную зону с несколькими «игрушками»: батут, мяч с физикой (синхронизируется хостом), сцена для танца;
- после первого финиша стартует отсчёт 90 с; забег заканчивается, когда финишировали все или отсчёт истёк;
- игроки, не дошедшие до конца, всё равно попадают на экран результатов.

## 8. Сетевая архитектура и синхронизация

Топология — listen-server: создатель лобби становится хостом и играет сам, остальные подключаются к нему звездой через Steam Relay. Каждый клиент авторитетен только над движением своего персонажа, всё, что даёт награду или меняет мир, решает хост.

```
   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │   Клиент     │   │   Клиент     │   │   Клиент     │
   │ свой перс.   │   │ свой перс.   │   │ свой перс.   │
   │ 20 Гц,       │   │ 20 Гц,       │   │ 20 Гц,       │
   │ интерполяция │   │ интерполяция │   │ интерполяция │
   └──────┬───────┘   └──────┬───────┘   └──────┬───────┘
          │                  │                  │
   ═══════╧══════════════════╧══════════════════╧═══════
        Steam Datagram Relay: P2P, IP игроков скрыты
   ══════════════════════════╤══════════════════════════
                             │  снапшоты 20 Гц, RPC, голос
            ┌────────────────┴─────────────────┐
            │ ХОСТ (создатель лобби, играет)   │
            │ авторитет: мобы, монеты, ворота, │
            │ помощь; ретрансляция снапшотов   │
            │ и голоса; часы забега и seed     │
            └───────┬────────────────┬─────────┘
                    │                │
     ┌──────────────┴───────┐  ┌─────┴───────────────────┐
     │ Steam: лобби, друзья,│  │ Webhook жалоб           │
     │ оверлей, инвайты,    │  │ POST: кто, на кого,     │
     │ Rich Presence        │  │ причина (URL вне репо)  │
     └──────────────────────┘  └─────────────────────────┘
```

Клиенты не общаются напрямую: снапшоты и голос идут через хост, поэтому хост может фильтровать голос по дистанции.

**Транспорт.** `net/transport.gd` задаёт интерфейс `host_game()`, `join_game(target)`, `close()` и сигналы подключения. `EnetTransport` работает на localhost для разработки, `SteamTransport` — через SteamMultiplayerPeer и id лобби. Весь остальной код не знает, какой транспорт активен. Выбор: аргумент `--dev-host`/`--dev-join` или отсутствие Steam → ENet, иначе Steam.

**Авторитет:**

| Объект | Кто решает | Как синхронизируется |
| --- | --- | --- |
| Движение своего персонажа | Клиент-владелец | Снапшот 20 Гц, unreliable ordered |
| Атака (анимация) | Клиент-владелец | RPC reliable, всем |
| Попадание по мобу, смерть моба | Хост | Запрос клиента → проверка → рассылка |
| Подбор монеты | Хост | Первый запрос выигрывает |
| Состояние «Висит», помощь, чекпоинт | Хост | RPC reliable |
| Плиты, ворота, лестницы, падающие платформы | Хост | RPC reliable по событию |
| Позиции мобов и движущихся платформ | Никто (детерминизм) | Считаются от seed и `run_time` |
| Эмоции | Клиент | RPC через хост, фильтр по радиусу |
| Голос | Клиент | Отдельный канал, фильтр по радиусу на хосте |
| Старт, финиш, конец забега | Хост | RPC reliable |

**Каналы:**

| Канал | Режим | Содержимое |
| --- | --- | --- |
| 0 | reliable | События игры, старт/финиш, награды |
| 1 | unreliable ordered | Снапшоты движения |
| 2 | unreliable ordered | Голосовые пакеты |

**Снапшот игрока** (упаковывается в `PackedByteArray`, около 20 байт): `seq` uint16, `x`, `y` float32, `vx`, `vy` int16, `anim_state` uint8, `flags` uint8 (направление взгляда, на земле, висит, говорит). Клиент отправляет свой снапшот хосту 20 раз в секунду, хост пересылает его остальным без изменений.

**Интерполяция чужих игроков:**

- буфер снапшотов, отрисовка с задержкой 100 мс по часам хоста, линейная интерполяция позиции;
- при отсутствии данных — экстраполяция не дольше 150 мс, затем персонаж замирает;
- при расхождении больше 256 px — телепорт без сглаживания;
- отбрасывать снапшоты со старым `seq`.

**Синхронизация часов:** клиент раз в секунду шлёт хосту ping с локальным временем, хост отвечает своим временем. Смещение = время хоста + RTT/2 − локальное время, сглаживание скользящим средним по последним 8 замерам. `run_time` везде считается по часам хоста.

**Старт забега:**

1. Хост генерирует seed и шлёт `rpc_start_run(seed, roster)`, записывает seed в данные лобби.
2. Все загружают `run.tscn` и собирают уровень, затем шлют `rpc_client_ready()`.
3. Когда готовы все (или прошло 15 с), хост шлёт `rpc_go(start_host_time)`, где старт на 3 с позже текущего времени; у всех идёт отсчёт 3-2-1.

**Отключения:**

- клиент отключился — его персонаж исчезает с эффектом, в результатах он остаётся с пометкой «вышел»;
- хост отключился — забег завершается у всех с сообщением «Хост покинул игру», показывается экран результатов по локальным данным. Миграция хоста — после MVP;
- подключение к уже идущему забегу запрещено (лобби становится недоступным для входа при старте).

**Версия протокола:** константа `PROTOCOL_VERSION` в `protocol.gd` записывается в данные лобби; лобби с другой версией не показываются и не принимаются.

**Лимиты:** `MAX_PLAYERS = 12` (код должен работать до 16), `MIN_PLAYERS_TO_START = 2` в режиме разработки и 3 на плейтестах. Бюджет трафика — не более 30 КБ/с на приём у клиента и 150 КБ/с на отдачу у хоста при 12 игроках с голосом.

## 9. Steam: лобби, матчмейкинг, друзья, инвайты

Всё социальное и матчмейкинг в MVP реализуется на Steam Lobby API и оверлее Steam; `SteamService` — единственный автолоад, который вызывает GodotSteam, остальной код работает с его сигналами и методами.

**Инициализация:**

- при старте игры `SteamService` инициализирует Steam; при ошибке игра показывает окно «Steam не запущен» с кнопкой «Играть офлайн (режим разработки)», которая включает ENet;
- из Steam берутся SteamID, имя (persona name) и аватар игрока;
- колбэки Steam обрабатываются каждый кадр (`run_callbacks` или встроенная обработка в выбранной версии GodotSteam).

**Данные лобби (ключ → значение):**

| Ключ | Значение |
| --- | --- |
| `game` | Уникальный тег игры, например `blockparty` (обязателен при App ID 480) |
| `ver` | `PROTOCOL_VERSION` |
| `state` | `waiting` или `running` |
| `mode` | `public` или `private` |
| `seed` | seed текущего забега |
| `host_name` | Имя хоста для отладки |

**Быстрая игра (кнопка «Играть»):**

1. Запрос списка лобби с фильтрами: `game` = тег игры, `ver` = своя версия, `state` = `waiting`, `mode` = `public`, есть свободные места.
2. Из найденных выбирается лобби с наибольшим числом игроков (быстрее наберётся), при равенстве — случайное.
3. Если ничего нет — создаётся новое публичное лобби на `MAX_PLAYERS` мест, игрок становится хостом.
4. Перед входом проверяется блок-лист: если в лобби есть заблокированный игрок, лобби пропускается.
5. Поиск повторяется каждые 5 с, пока игрок ждёт один в своём лобби: если нашлось лобби с игроками, он переходит туда (своё лобби закрывается). Так одиночные хосты сливаются.

**Лобби и старт:**

- экран лобби — маленькая игровая комната, где уже можно бегать, говорить и отправлять эмоции (раздел 13);
- когда в лобби `MIN_PLAYERS_TO_START` и больше, запускается отсчёт 30 с; при заполнении лобби отсчёт сокращается до 5 с;
- при старте хост ставит `state = running` и делает лобби недоступным для входа.

**Игра с друзьями (кнопка «С друзьями»):**

- создаётся лобби типа «только для друзей» или «приватное» с `mode = private`;
- кнопка «Пригласить» открывает стандартный диалог приглашения оверлея Steam;
- обрабатывается запрос входа из оверлея (друг нажал «Присоединиться») и параметр командной строки `+connect_lobby <id>`, если игра была закрыта;
- хост приватного лобби сам нажимает «Старт», минимум 2 игрока.

**Друзья:**

- кнопка «Добавить в друзья» на экране результатов и в списке игроков открывает оверлей Steam на странице добавления этого пользователя (`friendadd`);
- если игрок уже в друзьях Steam, вместо кнопки показывается метка «Друг»;
- друзья в MVP — это друзья Steam, собственного списка друзей нет.

**Rich Presence:** игра выставляет ключ `status` («В меню», «В лобби», «В забеге») и `connect` для присоединения через список друзей Steam. Локализованное отображение (`steam_display`) настраивается позже, когда будет свой App ID.

**Ещё раз с этой компанией:** на экране результатов кнопка голосования. Когда её нажали 2 и больше игроков, первый проголосовавший становится хостом нового приватного лобби, остальные проголосовавшие входят в него автоматически (id лобби рассылается через RPC до закрытия текущей сессии). Недоголосовавшие через 20 с уходят в меню.

## 10. Голосовой чат: push-to-talk и proximity

Голос записывается и сжимается Steam Voice, передаётся через хост по отдельному каналу, а громкость каждого говорящего считается на клиенте по расстоянию до него. Микрофон включён только пока зажата клавиша.

**Запись и отправка:**

- при нажатии PTT (по умолчанию V) вызывается старт записи Steam Voice, при отпускании — остановка (Steam сам дописывает хвост фразы);
- каждый кадр забираются доступные сжатые данные голоса; если они есть, отправляется `rpc_voice(packet)` хосту по каналу 2;
- флаг «говорит» в снапшоте включён, пока зажата PTT, — по нему у персонажа рисуется иконка динамика;
- в режиме разработки без Steam голос отключён (или реализуется позже через `AudioEffectCapture` + Opus, не блокирует MVP).

**Ретрансляция на хосте:**

- хост пересылает пакет только тем игрокам, кто ближе 1600 px к говорящему (по последним снапшотам), — экономия трафика;
- в лобби, на финишной площадке и на экране результатов фильтр по расстоянию не применяется: слышно всех;
- хост не пересылает голос игроку, который заблокировал говорящего (блок-лист клиент сообщает хосту при входе).

**Воспроизведение:**

- у каждого удалённого игрока свой `AudioStreamPlayer` с `AudioStreamGenerator`; полученные пакеты распаковываются (декомпрессия Steam Voice с оптимальной частотой дискретизации) и дописываются в буфер генератора;
- громкость по горизонтальному расстоянию d до говорящего: при d ≤ 640 px — 100%, от 640 до 1280 px линейно падает до 0, дальше 1280 px — тишина;
- лёгкая стерео-панорама по стороне экрана (−0.5…+0.5);
- одновременно воспроизводятся не больше 6 ближайших говорящих, остальные глушатся;
- джиттер-буфер 60–100 мс, при переполнении старые данные отбрасываются.

**Управление и настройки:**

| Настройка | Где | Значение по умолчанию |
| --- | --- | --- |
| Клавиша PTT | Настройки | V |
| Режим PTT: удержание / переключение | Настройки | Удержание |
| Общая громкость голоса | Настройки | 100% |
| Громкость конкретного игрока | Список игроков (Tab) | 100% |
| Заглушить игрока | Список игроков, экран результатов | Выкл. |
| Проверка микрофона (петля на себя) | Настройки | — |
| Отключить весь голос | Настройки | Выкл. |

**Индикация:** иконка динамика над говорящим, мигающая иконка микрофона в HUD, пока игрок сам говорит. Если игрок заглушён — зачёркнутый динамик над ним.

## 11. Экран результатов и социальные действия

Экран результатов — главная фича MVP: сверху до 5 карточек людей, с которыми у игрока было реальное взаимодействие, с конкретным «моментом», и только ниже — свёрнутый список остальных. Никаких мест и времени финиша.

**Учёт взаимодействий (`Interactions`, считается на каждом клиенте для себя):**

| Событие | Источник | Очки |
| --- | --- | --- |
| Секунда рядом (расстояние < 400 px) | Локально по снапшотам | 0.1 за секунду, не больше 15 за забег |
| Слышал голос игрока (секунда воспроизведения) | Локально | 0.3 за секунду, не больше 20 |
| Он вытянул меня / я вытянул его | Событие хоста | 10 |
| Вместе открыли кооп-ворота | Событие хоста | 6 |
| Прыгнул с его головы / он с моей | Локально (контакт сверху) | 4 |
| Вместе убили золотую цель | Событие хоста | 6 |
| Эмоция в ответ на его эмоцию в течение 5 с | Локально | 2, не больше 6 |

**Карточка «момента»:** для каждого из топ-5 выбирается самое весомое событие и превращается в фразу. Шаблоны (ключи перевода):

- «Вытащил тебя из пропасти на 3-й секции»;
- «Ты вытащил его из пропасти»;
- «Вместе открыли ворота»;
- «Подсадил тебя на уступ»;
- «Болтали 2 минуты»;
- «Бежали рядом почти весь забег» — если ярких событий нет.

**Содержимое экрана:**

1. Заголовок: «Забег пройден» или «Время вышло», общие итоги команды: сколько человек дошло, сколько раз помогали друг другу, сколько открыли ворот.
2. Личные итоги: монеты за забег, помощи, эмоции.
3. Блок «Ты бежал с ними»: до 5 карточек (аватар Steam, ник, скин, фраза-момент) и кнопки.
4. Свёрнутый список «Остальные участники» с теми же кнопками, раскрывается кликом.
5. Кнопки внизу: «Ещё раз с этой компанией» (голосование, раздел 9), «Новый забег» (быстрая игра), «В меню».

**Кнопки у игрока:**

- «Добавить в друзья» — оверлей Steam (раздел 9), у уже друзей — метка «Друг»;
- три симпатии: «Круто бежал», «Смешной», «Помог мне». Каждый игрок раздаёт до 3 симпатий за забег, одному человеку — не больше одной. Симпатии рассылаются через хост, получатель видит всплывающее уведомление «Тебе поставили: Помог мне» и счётчик в итогах;
- меню «…»: заглушить, заблокировать, пожаловаться (раздел 12).

**Сессия после забега:** сетевое соединение живо, пока экран результатов открыт (максимум 60 с или пока хост не вышел), чтобы работали симпатии и голосование. Голос на этом экране работает для всех без фильтра расстояния.

**Лог плейтеста:** по окончании забега в `user://logs/runs.jsonl` пишется строка: id забега, число игроков, длительность, нажимал ли PTT, суммарное время речи, число заявок в друзья, симпатий, голос за повтор. Без личных данных других игроков, только хеши SteamID.

## 12. Безопасность: мут, блок, жалоба

Любой игрок должен заглушить или убрать неприятного человека за два клика в любой момент, и это работает с первого плейтеста. Все три действия доступны в списке игроков (Tab), в меню паузы и на экране результатов.

| Действие | Эффект | Хранение |
| --- | --- | --- |
| Заглушить | Не слышу его голос, не вижу его эмоции-фразы. Он об этом не знает | До конца сессии игры |
| Заблокировать | Всё, что делает «Заглушить», плюс: хост не пересылает мне его голос; быстрая игра не пускает меня в лобби, где он есть; его персонаж у меня полупрозрачный | Постоянно, в `user://save.json` (список SteamID), управление в настройках |
| Пожаловаться | Отправка жалобы на webhook, автоматически включает «Заблокировать» (с возможностью отменить) | На стороне приёмника |

**Жалоба:**

- причины: «Оскорбления», «Неприемлемый голос или поведение», «Читы», «Другое» (плюс необязательный комментарий до 200 символов);
- тело POST-запроса (JSON): SteamID жалобщика, SteamID нарушителя, их ники, причина, комментарий, id забега, UTC-время, версия игры;
- URL webhook берётся из `user://config.cfg` или переменной сборки, в репозиторий не коммитится; если URL не задан — жалоба пишется в локальный лог;
- запись голоса для доказательств в MVP не ведётся.

**Если заблокированный попал в моё лобби** (например, зашёл после меня): у меня он автоматически заглушён и полупрозрачен, на экране появляется ненавязчивое уведомление с кнопкой «Выйти из лобби». Если хост заблокировал игрока, хост его выкидывает из лобби до старта.

**Ники:** отображаются ники Steam; в MVP фильтр мата не делается, но длина ника в UI обрезается до 20 символов.

## 13. UI и поток экранов

Игрок проходит цикл «меню → лобби → забег → результаты → снова лобби», и от запуска игры до начала бега должно пройти не больше трёх кликов.

**Поток экранов:**

```
Boot ──► Главное меню ──► Лобби ──► Забег ──► Финишная площадка ──► Результаты
              ▲             ▲                                          │
              │             └──── «Ещё раз с этой компанией» ◄─────────┤
              │                   «Новый забег» (быстрая игра) ◄───────┤
              └────────────────── «В меню» ◄───────────────────────────┘
```

1. **Boot** — инициализация Steam, загрузка сохранения и настроек. При ошибке Steam — окно с выбором офлайн-режима.
2. **Главное меню** — «Играть», «С друзьями», «Гардероб», «Настройки», «Выход». Справа — персонаж игрока в текущем наряде, внизу — баланс монет.
3. **Лобби** — маленькая комната (одна секция без опасностей) с батутом; игроки бегают, говорят, шлют эмоции. Сверху: число игроков «5 / 12», отсчёт до старта, кнопка «Пригласить друзей», для хоста приватного лобби — «Старт».
4. **Забег** — HUD: монеты за забег, номер секции «3 / 10», таймер до конца забега (показывается только за последние 2 минуты), иконка микрофона, подсказки кнопок у интерактивных объектов.
5. **Финишная площадка** — отсчёт до конца забега, список ещё бегущих.
6. **Результаты** (раздел 11) → «Ещё раз с этой компанией» ведёт в новое лобби, «Новый забег» — в быструю игру, «В меню» — в главное меню.

**Оверлеи во время игры:**

- **Tab — список игроков:** ник, аватар, иконка «говорит», ползунок громкости, кнопки «Заглушить», «Заблокировать», «Пожаловаться», «Добавить в друзья». Игра при этом не останавливается;
- **Esc — меню:** «Продолжить», «Настройки», «Выйти из забега» (с подтверждением). Пауза невозможна, игра идёт;
- **Q — колесо эмоций** (раздел 7.5);
- **F3 — отладочная панель** (только в dev-сборке): FPS, пинг, число пиров, трафик вход/выход, `run_time`, seed, id секции.

**Над персонажами:** ник (скрыть можно в настройках), иконка динамика, пузырь эмоции, иконка «Висит — нужна помощь».

**Гардероб:** 3 категории — цвет тела (8 цветов), головной убор (6 шт.: кепка, корона, шапка, нимб, рожки, цветок), след при беге (4 шт.). Цена 20–150 монет, первые варианты в каждой категории бесплатны. Выбор сохраняется локально и передаётся другим игрокам при входе в лобби (`rpc_set_cosmetics`). Покупок за реальные деньги в MVP нет.

**Настройки:**

| Раздел | Параметры |
| --- | --- |
| Управление | Переназначение всех клавиш, сброс по умолчанию |
| Звук | Общая громкость, музыка, эффекты, голос, режим PTT, проверка микрофона |
| Экран | Полноэкранный / окно, разрешение, V-Sync, лимит FPS |
| Социальное | Показывать ники, отключить весь голос, список заблокированных с кнопкой «Разблокировать» |
| Язык | Русский, English |

**Требования к UI:** весь UI на `Control`-нодах с общей темой (`ui/theme.tres`), масштабируется от 1280 × 720 до 3840 × 2160, навигация с клавиатуры и геймпада в меню, крупный читаемый шрифт с кириллицей (например, из Google Fonts под OFL).

## 14. Графика и звук на этапе MVP

В MVP графика — плейсхолдеры в блочном стиле, которые легко заменить: вся визуальная часть подключается через отдельные сцены и ресурсы, а геймплейный код не зависит от конкретных спрайтов.

**Стиль:** плоские блоки и кубы с простым затенением одной гранью (псевдо-3D), яркая пастельная палитра, толстый тёмный контур. Персонаж — «кубик» из головы и тела, руки и ноги — отдельные блоки, анимируются твинами.

**Источники временных ассетов:** генерация примитивами (`Polygon2D`, `ColorRect`, шейдер затенения) и паки Kenney под CC0. Никаких ассетов с неясной лицензией. Файл `assets/CREDITS.md` перечисляет каждый внешний ассет и его лицензию.

**Разделение визуала и логики:**

- `player.tscn` содержит узел `Visual` — отдельную сцену `player_visual.tscn`; смена наряда меняет только её параметры;
- у мобов и препятствий аналогично: логика и коллизии отдельно, визуал — дочерняя сцена;
- цвета палитры — в одном ресурсе `assets/palette.tres`.

**Эффекты (минимум):** частицы при ударе, при подборе монеты, при приземлении; вспышка при открытии ворот; конфетти на финише. Лёгкий параллакс фона из 2–3 слоёв.

**Звук:**

- звуки: прыжок, приземление, удар, попадание по мобу, монета, «вытянул», ворота открылись, эмоция, финиш, уведомление;
- музыка: один лёгкий трек для меню и лобби, один для забега (CC0/CC-BY с указанием в CREDITS);
- шины аудио: `Master`, `Music`, `SFX`, `Voice`; голос игроков идёт только в `Voice`;
- при речи любого игрока рядом музыка приглушается на 30% (ducking), чтобы голос был разборчивее.

## 15. Этапы разработки и критерии приёмки

Работа идёт строго по этапам: следующий начинается, только когда все критерии предыдущего проверены вручную и закоммичены. Каждый этап заканчивается коротким отчётом в `docs/STATUS.md`: что сделано, как проверить, что отложено.

### Этап 0. Каркас проекта

- создан проект Godot, структура папок из раздела 3, все автолоады-заглушки с комментариями;
- подключены GodotSteam и GUT, версии записаны в README;
- `Log` пишет в консоль и `user://logs/`;
- аргументы командной строки из раздела 3 разбираются;
- скрипты `tools/run_local.*` запускают хост и N клиентов.

**Критерии:** игра запускается; при запущенном Steam в логе SteamID и имя; без Steam — окно офлайн-режима; `run_local` открывает 4 окна; GUT запускает пустой тест.

### Этап 1. Одиночный геймплей

- персонаж с управлением и физикой из раздела 4, камера;
- 4 секции (по одной каждого типа) и сборка уровня по seed;
- пропасти с состоянием «Висит» и возвратом на чекпоинт, шипы, кактусы, движущиеся платформы;
- птицы и зверьки с детерминированным движением, атака, монеты;
- финишная площадка.

**Критерии:** уровень проходится от старта до финиша; при одном seed уровень одинаков при перезапуске; юнит-тест на детерминизм генератора (1000 seed) проходит; 60 FPS на встроенной графике.

### Этап 2. Сеть через ENet (без Steam)

- транспорт, снапшоты, интерполяция, синхронизация часов;
- старт забега по протоколу из раздела 8;
- авторитет хоста: мобы, монеты, чекпоинты, «Висит»;
- отладочная панель F3;
- режим `--bot`.

**Критерии:** 4 окна на одном ПК проходят забег вместе, движения других плавные; монета, подобранная одновременно двумя, достаётся одному; убитый моб исчезает у всех; при искусственной задержке 150 мс и потере 5% пакетов (эмуляция в транспорте) игра играбельна; 12 экземпляров (часть — боты) работают без падений.

### Этап 3. Кооп-механики

- вытягивание из пропасти, нажимные плиты и ворота с запасным таймером, «ступенька» с лестницей, золотая цель, эмоции и колесо, «Сюда!»;
- все 14 секций пула.

**Критерии:** каждая механика работает у 2 игроков по сети; при одном игроке забег проходится благодаря запасным таймерам; события помощи попадают в `Interactions`.

### Этап 4. Steam

- `SteamTransport` через SteamMultiplayerPeer;
- быстрая игра, лобби-комната, отсчёт, слияние одиночных лобби;
- приватное лобби, приглашения, вход через оверлей и `+connect_lobby`;
- Rich Presence.

**Критерии:** два разных Steam-аккаунта на двух ПК находят друг друга через «Играть» и проходят забег; приглашение другу работает из закрытой игры; лобби других игр на App ID 480 не видны; собрана Windows-версия: builds/blockparty-windows.zip (exe, pck, DLL GodotSteam и steam_api64.dll, steam_appid.txt), архив запускается на чистой Windows при открытом Steam.

### Этап 5. Голос

- PTT, отправка через хост, фильтр расстояния на хосте, воспроизведение с затуханием и панорамой, лимит 6 говорящих;
- настройки голоса, проверка микрофона, мут игрока.

**Критерии:** 3+ человека на разных ПК слышат друг друга без заиканий; громкость меняется с расстоянием и пропадает дальше 1280 px; заглушённый не слышен; задержка голоса субъективно ниже 300 мс; собрана Windows-версия: builds/blockparty-windows.zip (exe, pck, DLL GodotSteam и steam_api64.dll, steam_appid.txt), архив запускается на чистой Windows при открытом Steam.

### Этап 6. Результаты и социальное

- `Interactions`, экран результатов с карточками-моментами, симпатии, «Добавить в друзья», голосование «Ещё раз с этой компанией»;
- лог плейтеста `runs.jsonl`.

**Критерии:** после забега у игрока в топе те, с кем он реально взаимодействовал (проверка сценарием: помог одному, стоял рядом с другим); голосование переносит 2+ игроков в новое лобби; запись в `runs.jsonl` появляется; собрана Windows-версия: builds/blockparty-windows.zip (exe, pck, DLL GodotSteam и steam_api64.dll, steam_appid.txt), архив запускается на чистой Windows при открытом Steam.

### Этап 7. Безопасность, настройки, гардероб, сборка

- заглушить / заблокировать / пожаловаться во всех местах, блок-лист в матчмейкинге и на хосте, webhook;
- все настройки из раздела 13, локализация ru/en;
- гардероб и синхронизация косметики;
- экспорт Windows-сборки, загрузка в закрытую ветку Steam (после получения своего App ID).

**Критерии:** заблокированный игрок не попадает в моё новое лобби через быструю игру и не слышен; жалоба приходит на тестовый webhook; все строки UI переведены; чистая Windows-машина запускает сборку из Steam; собрана Windows-версия: builds/blockparty-windows.zip (exe, pck, DLL GodotSteam и steam_api64.dll, steam_appid.txt), архив запускается на чистой Windows при открытом Steam.

## 16. Тестирование, отладка, нефункциональные требования

Большая часть проверки сети делается на одном ПК через ENet и ботов; Steam-часть проверяется на двух машинах с двумя аккаунтами, потому что Steam не позволяет запустить две копии игры под одним аккаунтом.

**Нефункциональные требования:**

| Требование | Значение |
| --- | --- |
| FPS | 60 стабильно на встроенной графике Intel Iris Xe / AMD Vega уровня 2020 года, 12 игроков на экране |
| Время загрузки забега | Не больше 5 с |
| Пинг, при котором игра комфортна | До 150 мс |
| Трафик | До 30 КБ/с на приём у клиента, до 150 КБ/с на отдачу у хоста (раздел 8) |
| Память | До 1 ГБ ОЗУ |
| Размер сборки | До 300 МБ |
| Стабильность | Нет падений за 10 забегов подряд с 12 участниками (часть — боты) |
| ОС | Windows 10/11 x64 |

**Юнит-тесты (GUT), обязательные:**

- детерминизм генератора уровня: 1000 seed, два прогона, сравнение хешей списка секций и спавнов;
- упаковка и распаковка снапшота без потерь (кроме допустимого округления скоростей);
- расчёт позиции моба как функции времени — одинаковый результат при одинаковом входе;
- подсчёт очков `Interactions` и выбор фразы-момента на синтетических событиях;
- логика блок-листа: фильтрация лобби с заблокированным игроком.

**Инструменты отладки:**

- эмуляция плохой сети в `EnetTransport`: параметры задержки, джиттера и потерь через аргументы `--net-lag=150 --net-loss=5`;
- панель F3 (раздел 13);
- режим `--bot` для нагрузочных прогонов;
- все сетевые RPC логируются на уровне DEBUG с именем, отправителем и размером (включается флагом `--log-net`).

**Ручной чек-лист плейтеста** — в `docs/playtest_checklist.md`.

## 18. Работа с Claude Code

Правила для Claude Code лежат в `CLAUDE.md` в корне репозитория; текущий этап и отчёты — в `docs/STATUS.md`.

**Порядок первого запуска (Linux-сервер):**

1. Положить на сервер `mvp_kit.zip` и `setup_server.sh`, выполнить `bash setup_server.sh ~/mvp_kit.zip ~/game-mvp`. Скрипт ставит Godot, GUT и GodotSteam, распаковывает комплект, записывает версии в `docs/STATUS.md` и делает первый коммит.
2. Запустить Claude Code в `~/game-mvp` с задачей: «Прочитай CLAUDE.md и docs/SPEC.md. Выполни этап 0».
3. После каждого этапа проверить критерии: headless-часть проверяет агент на сервере, визуальную часть и Steam — человек на своём ПК (забрать репозиторий и открыть в Godot той же версии).

**Открытые вопросы, которые решает команда, а не Claude Code:**

- название игры и тег лобби вместо `blockparty`;
- регистрация своего App ID в Steam Direct (нужна к этапу 7);
- куда принимать жалобы (Discord-канал модераторов, форма, почта);
- возрастная политика перед публичным запуском.
